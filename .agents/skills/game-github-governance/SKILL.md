# game-github-governance

Version: 1.0.0 (2026-11-25).

Use studio root projects/independent-game-studio; read games.json, GAME_REGISTRY.md, VERSION_INVENTORY.json and target STATUS.md. Capture branch HEAD, source and artifact hashes, actual published URL and release tag; distinguish candidate, latest artifact, current release, history and idea. Use scoped non-main branch and PR; preserve old builds and evidence. English public documentation. Keep registry, machine-readable manifest, game README/STATUS, changelog, inventory and public portfolio links consistent when applicable. Build from pinned source, record checksums, verify permanent release artifact and actual deployment separately. Require explicit merge/release and live DB/security authority; no secrets or private evidence in public repo. Record conflicts, do not silently rewrite history; read back changed files. Do not infer release from version string or expiring CI artifact.

## Required output
Record scope, gate, identity, verdict, evidence and next step. Use the shared ledger contract; preserve approval boundaries and project-specific requirements. Never claim runtime verification not performed.
