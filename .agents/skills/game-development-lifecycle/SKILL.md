# game-development-lifecycle

Version: 1.0.0 (2026-11-25).

Read studio GAME_REGISTRY.md, games.json, target STATUS.md and IDEAS_BACKLOG.md. Distinguish idea approval from implementation and release approval. Research reference mechanics without copying proprietary assets/code; define original identity, core gameplay loop, win/loss, progression, balancing, target platforms, accessibility, saves, RU/EN/AZ and offline-first unless online is required. Prefer minimal HTML5 architecture and reuse approved utilities; build a playable vertical slice before expanding. Keep each game independent with source, build recipe, test fixtures, status, versioned artifacts and history. Validate gameplay, controls, AI, saves, performance and localization; apply game reliability and release gates. Do not label specification playable or candidate released.

## Required output
Record scope, gate, identity, verdict, evidence and next step. Use the shared ledger contract; preserve approval boundaries and project-specific requirements. Never claim runtime verification not performed.
